## 2. โครงการจำลอง

**2.1 ประชากรปกติ** สร้างวันที่ 0–449 ทุกบัญชี · P2P หนึ่ง event เป็นทั้งเงินออกของผู้โอนและเงินเข้าของผู้รับ · ร้านค้า บิล และเงินเดือนใช้ `txn_type` MERCHANT/BILL/PAYROLL กับ `payer_type`/`payee_type` ของตัวเอง จึงแยกจาก `P2P` ได้ · วันที่ 0 เสนอเป็น 2025-01-01 00:00 ICT (คำถาม 1)

**2.2 Ring / episode**
1. สุ่ม ring ต่อ split ตาม §1.2–1.3 พร้อม family, ช่วงทำงาน, seeder และ receiver pool ทุกบัญชีเป็น token ใหม่ ธนาคารตาม share และมีอยู่เฉพาะใน split นั้น ถ้า episode หรือ ring ต่ำกว่าขั้นต่ำ ให้เพิ่ม ring จาก stream เดิมจนถึงขั้นต่ำ
2. เหยื่อสุ่มแบบไม่คืนที่จาก PERSON ทั้งหมด (ถูกหลอกได้คนละครั้งเดียว)
3. สร้าง timeline สัมพัทธ์: [ค่าสมัคร] → ก้อน 1 → เงินล่อ → ก้อน 2 → … (เงินล่อตามหลังก้อน 1..n_seed) → [ช่วงค่าปลดล็อก] และหยุดเมื่อครบก้อนหรือชนเพดาน ก้อนกระจายให้ R บัญชีรับเป็นช่วงต่อเนื่องตามลำดับ (p .2 ย้อนกลับไปใช้บัญชีเดิม)
4. วาง start แบบ uniform ใน [ต้น window, ปลาย window − span] ทุก event จึงอยู่ใน split โดยไม่ต้องบีบเวลา ถ้า span ยาวกว่า window ให้สุ่ม variant ใหม่
5. ซ้อนลงบนกิจกรรมปกติของเหยื่อ ซึ่งไม่ถูกแก้
6. Label: เงินออกของเหยื่อทุกรายการ (รวมค่าสมัคร รายการที่ซอย hop ผ่าน QR และค่าปลดล็อก) = `TRANSACTION / CONFIRMED_SCAM / INJECTED` · เงินล่อติด label แยก (เสนอชื่อ `SEED_INFLOW`) · เงินหาทุนจากญาติและเงินไหลภายใน ring ไม่ติด label

**2.3 Variants / holdout** `SPLIT`, `LONG_GAP` และ `ON_US_HOP` สุ่มระดับ episode ในทุก split ส่วน HO1/HO2 สุ่มระดับ ring (แก๊งหนึ่งใช้วิธีเดียว) เฉพาะใน test และติด `is_holdout=1` แนะนำให้รายงานผล test ทั้งแบบรวมและไม่รวม holdout

**2.4 Hard negatives** จำนวน = Binomial(บัญชี × เดือน, อัตรา) ทั้งใน warm-up และทุก split · subject สุ่มจาก PERSON ทั้งหมดโดยไม่ดูคุณลักษณะ (ซ้ำกับเหยื่อได้) · วาง start แบบ 2.2 ข้อ 4 ให้ทั้งลำดับอยู่ใน split เดียว

**2.5 Mimicry** จาก HN ใน train (วันที่ 90–269) เก็บ tuple ต่อ HN หนึ่งชุด: (เวลาจากเงินออกถึงเงินเข้าครั้งแรก, ยอดเข้า ÷ ยอดออก, เวลาจากเงินเข้าถึงเงินออกถัดไป) episode ของ A ใน test มี `u_e` ~ U(0,1) จาก stream ของตัวเอง ถ้า `u_e < m` ให้แทนทั้งสามค่าในทุกรอบเงินล่อด้วย tuple ที่สุ่มแบบ joint (HO1 แทนยอดรวมของชิ้นแล้วแบ่งตามสัดส่วนเดิม) ชุด `m = .5` จึงเป็นส่วนย่อยของ `m = 1` ถ้า span ใหม่ไม่พอดี window ให้สุ่ม tuple ใหม่และบันทึกจำนวนครั้ง

**2.6 Determinism** ใช้ seed เดียว → `numpy.random.SeedSequence(seed).spawn` แยก stream ของประชากร, HN, ring แต่ละวง และ mimicry `event_id` และ token มาจาก hash ของ (seed, stream, ลำดับภายใน stream) จึงไม่ขึ้นกับการเรียงแถว เมื่อเปลี่ยน m แถวนอก episode ที่ถูก mimic จึงเหมือนเดิมทุกไบต์ เรียงผลตาม (`ts`, `event_id`) เขียนยอดทศนิยม 2 ตำแหน่งคงที่ และไม่ใช้เวลาจริงของเครื่อง

## 5. คำถามถึง detector side

1. ขอยืนยันวันที่ของวันที่ 0 (เสนอ 2025-01-01 00:00 ICT = epoch 1735664400) ต้องใช้กำหนดวันเงินเดือนและค่าเช่า

## 6. คำตอบจาก detector side (29 ก.ย. · ตอบเฉพาะ schema / ขอบเขต ไม่มี threshold · ช่วงพารามิเตอร์ใน §1 ไม่ถูกแก้)
